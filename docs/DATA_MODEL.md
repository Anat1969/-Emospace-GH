# מודל הנתונים

התיאור מבוסס על קובצי ההגירה והטיפוסים בפרויקט; אינו צילום של נתוני השירות החי.

| טבלה | תפקיד | קשר עיקרי |
| --- | --- | --- |
| `profiles` | פרטי משתמש | חשבון משתמש |
| `projects` | לקוח, פרטי תכנון, מצב וקישור שאלון | אדריכל בעל הפרויקט |
| `questionnaire_responses` | תשובה לכל חלק | `project_id` |
| `analysis_results` | מסמך ניתוח מובנה | `project_id` |
| `generated_images` | חדר, הנחיית יצירה וכתובת תמונה | `project_id` |

## שדות המשמשים בתהליך

- פרויקט: מזהה, בעלים, פרטי לקוח, סוג פרויקט, שטח, תקציב, מועד יעד, מצב ו־`questionnaire_token`.
- תשובה: `project_id`, `module_name`, `response_data`.
- תוצאה: `project_id`, `result_data`.
- הדמיה: פרויקט, שם חדר, הנחיית יצירה וכתובת התמונה שנוצרה.

לרשימת עמודות וסוגים מדויקת יש לעיין ב־`src/integrations/supabase/types.ts` וב־`supabase/migrations/`, ולא להסתמך על הטבלה התמציתית כאן.

## מצבים

הקוד משתמש ב־`draft`, `sent`, `completed` ו־`analyzed`. סיום שאלון מעדכן ל־`completed`; אחרי ניתוח המסך מעדכן ל־`analyzed`. המצב נשמר כמחרוזת ולא כמכונת מצבים מאומתת בכל השכבות.

## שמירה וקשרים

השאלון קורא תשובות לפי פרויקט ושומר לפי שם חלק. פונקציית הניתוח מעדכנת תוצאה קיימת או מוסיפה חדשה. אין להבטיח ייחודיות, הגנה מתחרות או מחיקה מדורגת בלי לבדוק את האילוצים בפועל.

## הרשאות

קיימות מדיניות RLS לבעלי פרויקטים לצד מדיניות ציבורית רחבה בהגירות. סינון לפי קישור בשאילתת המסך אינו מגביל כשלעצמו את ההרשאות. ראו [אבטחה ופרטיות](SECURITY.md).
