# התקנה ותפעול

## עבודה מקומית

נדרש עותק של **קוד האפליקציה** בנוסף למסמכים, סביבת Node.js התואמת ל־Vite 5 או Bun, וגישה מורשית ל־Lovable Cloud.

```sh
bun install
bun run dev
```

חלופה עם npm: `npm install` ואז `npm run dev`. קיימים במאגר כמה קובצי נעילת חבילות; אין לערבב מנהלי חבילות באותו שינוי.

## משתני סביבה

| משתנה | שימוש |
| --- | --- |
| `VITE_SUPABASE_URL` | כתובת שירות החיבור של הלקוח |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | מפתח ציבורי של הלקוח |
| `LOVABLE_API_KEY` | קריאות AI בפונקציות בלבד |

שמות משתני הלקוח הם שמות טכניים של החיבור המנוהל. אין במסמך ערכים אמיתיים. אין להכניס מפתחות פרטיים למשתנים שמתחילים ב־`VITE_`; הם נחשפים לדפדפן. בפרויקט מנוהל לא עורכים ידנית את `.env`, קובצי החיבור או `supabase/config.toml`.

## שירותים

הסביבה המקומית אינה יוצרת משתמשים, טבלאות או פונקציות. קובצי ההגירה נמצאים ב־`supabase/migrations/`; שינוי נתונים או הרשאות מחייב יישום מפורש ובדיקה ב־Lovable Cloud. פונקציות AI דורשות פריסה נפרדת לאחר שינוי. אין צורך לבקש מהמשתמש מפתח שירות מנוהל.

## פקודות הפרויקט

`bun run test` לבדיקות, `bun run test:watch` למצב מעקב, `bun run lint` לבדיקת קוד, `bun run build` לאריזת ייצור ו־`bun run preview` לתצוגת האריזה המקומית. בתוך Lovable האריזה מתבצעת אוטומטית.

## GitHub ואירוח

שמירת מסמכים דרך GitHub אינה מחברת סנכרון קוד. חיבור Git sync נעשה מתוך הגדרות הפרויקט → Git. יש לבדוק את החיבור שם; אין להסיק אותו מהימצאות מאגר.

באירוח עצמאי יש להגדיר החזרת עמוד האפליקציה גם לכתובות פנימיות, אחרת רענון עמוד פרויקט עלול להחזיר 404. יש להגדיר משתני סביבה וכתובות חזרה לכניסה בהתאם לאירוח. פרסום האתר אינו חלק ממשימת התיעוד.
